# Seed Cracker: техническое задание

Клиентский Fabric мод для Minecraft Java 26.2. На любом сервере вычисляет полный 64-битный сид по
тому, что клиент уже получил, и превращает его в удобный поиск по верхнему миру и незеру. Энд не
входит (для него End City Finder).

## 1. Требования

1. **Только клиент.** Ничего не отправлять на сервер, никаких пакетов, команд или чатов.
2. **Сам собирает данные.** Структуры и биомы из прогруженных чанков, хэш сида из пакета входа.
   Ручной ввод только как запасной вариант.
3. **Быстро.** Типичный случай (несколько храмов, кораблей или деревень) решается за секунды
   на обычном ПК, худший (только незер) за минуты, с прогрессом и оценкой времени.
4. **Точно как в игре.** Поиск структур и биомов совпадает с `/locate` 26.2, с проверкой биомов,
   рельефа, исключений и выбора вида структуры.
5. **Поиск.** Экран с поиском по названию (рус/англ), категории структур и биомов текущего
   измерения, ближайшие результаты с расстоянием и координатами, выбор цели кликом.
6. **Линии.** Красивая анимированная линия до цели: дуга, градиент, бегущие импульсы, свечение,
   маяк и кольцо у цели, маркер на горизонте для дальних целей. Метки для отслеживаемых типов.
7. **Карта.** Карта биомов по сиду со структурами, игроком и целью.
8. **Без энда.** Только `minecraft:overworld` и `minecraft:the_nether`.

## 2. Сид структур (48 бит)

Все `random_spread` наборы сеют `java.util.Random` значением
`rx * 341873128712 + rz * 132897987541 + seed + salt`, то есть первое состояние
`s1 = ((seed + K) ^ M) * a + c (mod 2^48)`, смещение по X это `nextInt(n)` из `s1`, по Z из `s2`.

* **Подъём младших бит.** Если `n = 2^k * m`, то `offset mod 2^k` равен битам 17..17+k-1 состояния,
  а они зависят только от младших 17+k бит сида. Пирамиды, храмы, иглу, хижины, аванпосты (n=24)
  дают 3 бита на ось, корабли (20) и руины (12) по 2, деревни, руины троп (26) и камеры (22) по 1.
  Перебираются 2^20 младших вариантов, остаются совместимые.
* **Старшие 13 бит.** `M` занимает 35 бит, поэтому при известных младших 35 битах старшие 13 бит
  `s1` равны `(B + h * a) mod 2^13`. Клад (`nextFloat() < 0.01` на соли 10387320) и делитель-степень
  двойки (древние города, 16) задают для них интервал, нечётная часть `m` задаёт остаток
  по модулю `m` (через обратный к `2^18`). Интервалы пересекаются, остатки склеиваются по КТО,
  и кандидаты на `h` выписываются напрямую, без перебора 8192 значений.
* Остальное проверяется на каждом кандидате с ранним выходом: смещения всех структур (включая
  треугольные), частота аванпостов (`legacy_type_1`), их зона исключения от деревень, кладов
  (`legacy_type_2`), шахт (`legacy_type_3`), поворот стартового куска (первый `nextInt(4)` от
  `setLargeFeatureSeed`), выбор крепость/бастион (`nextInt(5)`, с поправкой на базальтовые дельты).
* Сложность ≈ (младшие варианты) × 2^(35-L) × (кандидаты на пару). Оценка времени считается до
  старта; если больше лимита (20 минут), перебор ждёт `/sc crack`.
* Если вариантов много, они хранятся (до 4096) и просто фильтруются новыми находками.

## 3. Полный сид (ещё 16 бит)

1. **Хэш.** Сервер шлёт `BiomeManager.obfuscateSeed(seed)` (первые 8 байт SHA-256) в пакете входа,
   клиент хранит его в `BiomeManager.biomeZoomSeed`. 65536 вариантов SHA, миллисекунды.
2. **Биомы**, если хэша нет или он подменён. Мод хранит до 64 разнесённых ячеек биомов
   на измерение из присланных чанков. Для каждого из 65536 вариантов строится `RandomState`,
   в котором роутер шума урезан до шести функций климата (остальное заменено константами), и
   сверяются биомы с допуском на смешение у старых чанков. Сначала пробуются 0x0000 и 0xFFFF
   (текстовые и короткие числовые сиды).
3. Найденный сид проверяется по биомам обоих измерений.

## 4. Распознавание структур

Источник это блоки прогруженных чанков (сервер шлёт и подземные секции).

* **По шаблону.** Стартовые шаблоны берутся из ванильных данных во время игры: деревни (все
  центры, включая зомби), древние города, руины троп, камеры испытаний, бастион-мост, иглу,
  корабли, большие подводные руины, разрушенные порталы. Блоки нормализуются (мох, трещины,
  заражённые, старение меди, плачущий обсидиан, породы дерева у кораблей). Для каждого шаблона
  выбирается редкий якорный блок (колокол, печь, обсидиан, мозаика…). Каждое вхождение якоря
  даёт для каждого поворота и отражения одно положение шаблона, и выживают только те, где
  стартовый чанк выровнен по 16. Оставшиеся проверяются поблочно (порог 70–80%). Правила
  положения (центр jigsaw-старта, якорь `city_anchor`, пивоты иглу, кораблей и порталов) проверены
  тестом против кусков, которые строит ваниль.
* **По сигнатуре.** Пирамида: синяя терракота с оранжевой вокруг в точке (10, 10) стартового чанка.
  Храм в джунглях и хижина целиком лежат в стартовом чанке (липкие поршни и раздатчики, котёл и
  верстак, плюс биом). Монумент: габарит призмарина 58×58 вокруг угла стартового чанка (ждёт, пока
  прогрузятся соседние чанки). Адская крепость: крестообразный мост 19×19 из адского кирпича с углом
  в (2, 2) стартового чанка, открытым проходом над настилом и пустыми углами (сплошные кирпичные
  массы замков не подходят).
  Клад: сундук в (9, 9) чанка под песком или камнем на пляже.
* Поиск якорей ограничен по биомам структуры (из её тега) и по числу якорей на чанк.

## 5. Модель мира

`RegistryDataLoader` грузит все реестры генерации с тегами из встроенного ванильного датапака, как
новый сервер. Для сида строятся `MultiNoiseBiomeSource`, `NoiseBasedChunkGenerator`, `RandomState` и
`ChunkGeneratorStructureState`. Поиск идёт по регионам наборов, для каждого кандидата вызывается та
же логика, что в `ChunkGenerator.createStructures` (выбор вида структуры, `findValidGenerationPoint`),
куски строятся только по требованию (рамка, комната с порталом, спавнеры ифритов). Крепости берутся из
колец `getRingPositionsFor`. Всё это идёт в фоновом потоке, интерфейс только читает готовые ответы.

## 6. Интерфейс

* HUD: строка статуса и компас до цели.
* Экран поиска (B), карта (M), переключатель линий (V), команды `/sc`.
* Линии через ванильные гизмо (видны сквозь блоки).

## 7. Проверка

* Юнит-тесты ядра без Minecraft.
* Сверка с кодом 26.2: расстановка всех наборов, частоты и исключения, хэш, повороты, геометрия
  шаблонов с поиском от якоря, урезанный климат, слайм-чанки, крепости, поиск, сквозной взлом.
* Клиентский геймтест: настоящий клиент и сервер с известным сидом и обычным (не плоским) миром.
  Бот облетает 13 структур обоих измерений, каждая должна найтись, ни одна находка не должна указывать
  на чанк без такой структуры, сид должен взломаться, поиск совпасть с ванилью.

## 8. Риски

* Изменения генерации в обновлениях ловятся тестами против ванили.
* Изменённые соли (Spigot/Paper) и датапаки: честно сообщаем «не сходится».
* Ложное распознавание: наблюдения можно удалить, противоречие видно сразу.
