# End City Finder: техническое задание

Клиентский Fabric мод для Minecraft Java 26.2. По нескольким найденным городам края
и обсидиановым пилонам на главном острове восстанавливает раскладку энда и показывает
все остальные города прямо в мире, на HUD и на карте. Работает на чужих серверах:
ничего не отправляет на сервер, только смотрит на чанки, которые клиент и так получил.

## 1. Почему это вообще решается

* Весь энд (рельеф, биомы, структуры, пилоны) зависит только от младших **48 бит** сида:
  везде используется `LegacyRandomSource`, который режет сид до 48 бит
  (`legacy_random_source: true` в настройках шума энда, `EndIslandDensityFunction`,
  `setLargeFeatureWithSalt`, `RandomSource.create(seed)` у пилонов и порталов).
  Значит нам нужен не полный сид, а 48 битный **structure seed**.
* **Города**: structure set `end_cities` это `random_spread`, spacing 20, separation 11,
  salt 10387313, spread `triangular`. Для региона `(rx, rz) = floorDiv(chunk, 20)`
  `setSeed(rx*341873128712 + rz*132897987541 + seed + salt)`, дальше
  `off = (nextInt(9) + nextInt(9)) / 2` сначала по X потом по Z.
  Каждый город с точным стартовым чанком даёт ~5.8 бит. Поворот города
  (`Rotation.getRandom` из `setLargeFeatureSeed(seed, cx, cz)`, это `nextInt(4)`)
  даёт ещё 2 бита.
  `nextInt(9)` с нечётной границей не раскладывается по младшим битам, поэтому
  в лоб это перебор 2^48, а это дни на CPU. Нужна ещё информация.
* **Пилоны**: `EndSpikeFeature.getSpikesForLevel`:
  `key = new LegacyRandom(seed).nextLong() & 0xFFFF`, затем
  `Util.toShuffledList(0..9, RandomSource.create(key))` даёт высоту `76 + 3k`,
  радиус `2 + k/3` и клетку `k ∈ {1,2}` для каждого из 10 пилонов на кольце радиуса 42.
  `key` это биты 16..31 второго состояния LCG, то есть функция только младших 32 бит
  сида, и для каждого из 2^16 вариантов младших 16 бит ровно одно значение
  следующих 16 бит подходит. Итого пилоны режут пространство до **2^32** кандидатов
  на один `key`.
* 2^32 кандидата с ранним отсевом по первому городу это секунды на нескольких ядрах.
  После 5–6 городов (с поворотами хватает 4) остаётся единственный кандидат.
  Остаток добивается проверкой валидности городов и сверкой рельефа.

## 2. Сбор данных (клиент, автоматически)

1. **Пилоны**. В энде на каждом тике проверяем 10 колонок пилонов (позиции по формуле
   `floor(42*cos(2*(-π + π/10*i)))`). Если чанк загружен: ищем верхний обсидиан внутри
   радиуса пилона и бедрок над ним. `height = y(бедрок)` или `topObsidian + 1`.
   `k = (height - 76) / 3`, сверяем с радиусом. Частичные данные тоже годятся,
   ключи просто фильтруются по известным пилонам.
2. **Города**. При загрузке чанка в энде быстро проверяем секции на блоки города
   (purpur_block, purpur_pillar, purpur_stairs, purpur_slab, end_stone_bricks, end_rod).
   Чанки с такими блоками склеиваются в кластеры. Для кластера ищем нижний ярус
   (`base_floor`): пивот шаблона лежит в `(16cx+7, y, 16cz+7)`, шаблон растёт от пивота
   в сторону, заданную поворотом. По углам нижнего яруса ищем угол с координатами
   `≡ 7 (mod 16)`: он даёт стартовый чанк и поворот. Если однозначно не вышло,
   город сохраняется с набором кандидатов (несколько чанков, поворот неизвестен).
3. **Ручной ввод**: `/ecf add` (город рядом с игроком, запускает детект по блокам),
   `/ecf add <x> <z>` (примерные координаты основания, допуск 16 блоков).
4. **Пустые чанки**. Загруженные чанки без блоков города это негативные данные:
   кандидат сида, который предсказывает там валидный город, отбрасывается.
5. **Рельеф**. Для сверки кандидатов берём сэмплы колонок (есть земля / пустота)
   вне городов.

Все данные сохраняются в `config/endcityfinder/<сервер или мир>.json`, чтобы не
бегать к пилонам повторно.

## 3. Солвер

1. Ключи пилонов: перебираем все 65536 `key`, оставляем совпавшие с наблюдениями.
   Без пилонов не стартуем, просим долететь до главного острова.
2. Для каждого `key`: 2^16 младших половинок × 2^16 старших бит. Внутренний цикл:
   города в порядке убывания информативности, ранний выход. Многопоточно,
   с прогрессом и отменой. Лимит на число кандидатов (если городов мало).
3. Фильтр кандидатов (точный):
   * каждый наблюдённый город должен быть валиден для кандидата
     (биом end_highlands/end_midlands, высота основания ≥ 60, поворот совпадает);
   * пустые загруженные чанки не должны содержать предсказанных валидных городов;
   * рельеф в сэмплах совпадает.
4. Результат: один structure seed (или несколько, тогда показываем пересечение и
   просим ещё город).

## 4. Предсказание городов

Для каждого региона в радиусе (по умолчанию 6000 блоков, настраивается):
потенциальный чанк → проверка валидности (биом + рельеф, как в ванилле) → город.
Для каждого города дополнительно генерируем раскладку частей (порт `EndCityPieces`)
и определяем **есть ли корабль** (элитры). Пересчёт ленивый, по мере полёта.

## 5. Визуал

* **В мире**: у каждого предсказанного города вертикальный луч высотой до неба,
  каркас стартового чанка и подпись `Город края · 1240 м · корабль`. Цвет:
  с кораблём золотой, без корабля фиолетовый, посещённый серый. Луч рисуется
  сквозь блоки, подпись масштабируется с дистанцией. Дальность настраивается.
* **HUD**: строка с ближайшим непосещённым городом: стрелка направления относительно
  взгляда, дистанция, координаты, корабль. Плюс статус солвера
  (`пилоны 10/10 · городов 4 · кандидатов 3 · считаю 63%`).
* **Карта** (клавиша `J`): полноэкранный вид сверху. Фон это биомы энда по шуму
  островов (highlands/midlands/barrens/small islands/пустота), поверх города
  (иконки по типу), игрок со стрелкой взгляда, исследованные чанки, зум колёсиком,
  перетаскивание мышью, клик по городу ставит его целью для HUD.
* **Чат**: `/ecf list` выводит ближайшие города с кликабельными координатами.
* Посещённым город становится автоматически, когда игрок пролетел в 48 блоках от
  основания; можно переключить вручную.

## 6. Команды и клавиши

* `/ecf status`, `/ecf solve`, `/ecf add [x z]`, `/ecf remove <id>`, `/ecf list [n]`,
  `/ecf clear`, `/ecf seed <structureSeed>` (если сид уже известен),
  `/ecf visited <id>`, `/ecf target <id>`, `/ecf render on|off`.
* Клавиши: `J` карта, `K` переключить рендер в мире, `L` добавить город рядом.

## 7. Проверка

* Ядро без зависимостей от Minecraft, юнит тесты локально.
* Сверка ядра с cubiomes (эталонная C библиотека) на случайных сидах:
  позиции городов, валидность, корабли, высоты рельефа, пилоны.
* В CI: сверка ядра с ванильным кодом 26.2 (`VanillaRegistries`, настоящий
  `NoiseBasedChunkGenerator`, `EndSpikeFeature`) и сквозной тест: случайный сид →
  ванильные города и пилоны → солвер по 5 городам → предсказание остальных совпадает.
* Сборка мода в CI на каждый пуш.

## 8. Риски

* Mojang поменяет алгоритм пилонов или городов: ловится CI тестом против ваниллы.
* Ошибка детекта стартового чанка: город хранится с набором кандидатов,
  солвер учитывает OR.
* Игроки ломают пилоны: берём максимум по нескольким колонкам внутри радиуса и
  бедрок сверху, неуверенные пилоны не используем.
